## 2026-11-24 修复：真实包绑定丢失（Muse 直接修复）

针对真实画布导出包（15 段 60 镜）实测出的问题修了导入器：`bindings()` 改成人物取“存量 charIds 与格子文本点名”的交集、场景/道具以存量 assetIds 为准并用名字匹配补充；场景库从 `assets` 里 `category: 'scene'` 的条目派生（真实包无顶层 `scenes`）；顶层 `images[]` 的四宫格图总提示词读出来显示在分镜详情和提示词工作台；坏数据（画面描述含 `##` 场标题残留）报红、`bind` 的资源不在库中报红；参考图超 9 张时按四宫格图、人物、场景、道具取前 9 张并在一致性检查里点名未提交的图，不拦生成。导入诊断新增库数量、每段绑定、带四宫格总提示词的段数。

验证：新增 `test/fixtures/real-shape-project.json`（真实包形状的合成包）与 3 项回归测试；`node --test` 8/9 通过，唯一失败是 Windows FFmpeg 本地 MP4 拼接测试（Linux 沙箱无 `ffmpeg.exe`，改前基线同样失败）。用真实包原文实跑：15 段存量绑定 67 项 0 丢失，段 1 绑定含卡片、空气墙，拼好的提示词含卡片、空气墙，场景库 2 个，15 段四宫格总提示词全在；段 14、15 共 8 镜画面描述含场标题残留，已报红——这是画布导出数据本身的问题，须回画布重拆分镜后重新导出，桌面修不了。台词说话人导出包本身没带（14 镜 0 人），桌面不自编。


## 2026-11-25 修复：1.2.0 问题 + 模型按 Key 自动获取

- 模型选择改成按 Key 自动获取：设置里点「刷新模型列表」（保存设置后也会自动刷新一次），分别调 MiniMax `GET /v1/models` 与 DeepSeek `GET /models`，拉取该账号可用的模型后用户自己在下拉里选；选择持久化在设置里。MiniMax 只留 V2 视频生成可用的 H3 系列（`MiniMax-H3`、`MiniMax-H3-Max`），Hailuo 旧模型走 V1 接口、本软件不用，图片/语音/文本模型不进视频下拉；拉不到可用模型时回退内置列表。换模型后旧片段不复用（提交指纹已含模型）。
- 默认 DeepSeek 模型问题：旧默认 `deepseek-chat` 已停用，改成从拉取的列表里取，列表里没有旧选择时自动选第一个。
- 四宫格总提示词：核查结论是不进生成提示词——它是给生图用的 2×2 排版指令（“一张 1:1 正方形图，2×2 四宫格排版……”），原样放进视频提示词会误导模型；视频提示词里整体设定、资产锁、格位对照、逐镜台词已覆盖其内容，仍只在界面显示。
- 拟音标注：字幕与音轨里「混入分镜拟音」改名「混入分镜拟音（程序合成）」，并注明是程序合成的提示音、不是真实录音。
- 旧版清理：项目顶栏新增「清理旧版」，只保留当前最新版，删掉同一画布的旧版文件与记录；生成中的旧版不删。
- 本地转高清进度：FFmpeg 用 `-progress` 回传处理进度，界面实时显示百分比；仍为 CPU 重编码。

验证：新增 2 项测试（模型列表解析与回退、刷新保留选择＋指纹含模型＋清理旧版）。测试已写、未在沙箱执行，请在 Windows 上跑 `npm test`；模型拉取需真 Key 实测。
